# Owl-L demo media (GIF, promo videos, thumbnail)

A scripted, repeatable pipeline: it starts the **real app**, drives it like a person (mouse, keyboard, global shortcuts, real drag-and-drop), records the screen, and renders the files. One command regenerates everything for a new release. Nothing here is part of the app.

Everything it shows is **made up** (a German article, a sign, a subtitled video and a Word file, all generated by `py/make_assets.py`). It never uses real files, a real profile, or any recording of a real meeting.

## Where things live

| What | Where |
|---|---|
| Scripts, storyboard (this folder) | `owll/media/`, versioned with the app (the pipeline drives that app's UI, so the two change together) |
| Recordings, generated assets, fake profile | `E:\SecondDawn\media\work\` (outside the repositories) |
| Final files | `E:\SecondDawn\media\out\` (outside the repositories) |
| README GIF / WebP | `owll/docs/images/demo.gif`, `demo.webp` (the only generated files that are committed) |

Change the base folder with the environment variable `OWLL_MEDIA_DIR`. `node_modules/` and `.venv/` are ignored by git.

## Requirements

- Windows 10/11, **display scaling 100%**, a primary monitor of at least **2400 x 1350** (a 16:9 region of it is recorded; the taskbar and the notification corner stay outside of it). The script checks this first and says what is wrong.
- Node.js 20+, Python 3.12. An NVIDIA card is used for fast video encoding (`py/record.py` can fall back to `libx264`).
- The installed Owl-L must be **closed** (only one Owl-L can run at a time). Do not use the mouse or keyboard while it records: the script has the input, and a backdrop window covers your desktop, so nothing of it is recorded.
- The language packs and the Quality mode models are read from your normal model store (linked into the fake profile, never changed).

Pinned tools: `ffmpeg-static 5.2.0` (ffmpeg 6.0 essentials, Gyan build) and `ffprobe-static 3.1.0` in `package.json` and `package-lock.json`; Python packages in `requirements.txt` (including `kokoro-onnx`, `librosa`, `pymupdf`). The documents scene needs **Microsoft Word** (it is only used invisibly, to turn the two .docx files into pictures; no window, no account name on screen).

## Usage (PowerShell, in `owll/media`)

```powershell
.\make-demo.ps1 -Steps build               # once per release: builds the demo version of Owl-L (about 15 minutes)
.\make-demo.ps1                            # everything: assets, record all scenes, render all videos, GIF, thumbnail
.\make-demo.ps1 -Steps record -Scenes 03-popup          # re-record one scene
.\make-demo.ps1 -Steps render -Formats 9x16             # re-render one format
.\make-demo.ps1 -Steps gif,thumb           # only the README GIF and the thumbnail
```

Scenes: `02-text`, `03-popup`, `04-capture`, `05-live`, `05b-meeting`, `06-docs`, `07-write`. The hook and the outro are title cards; the offline scene reuses `02-text`. Each scene is its own clip, so one can be re-recorded alone (then run `render` again). The script ends by stopping only the processes the demo started (`py/cleanup.py`).

## How it works

- **Storyboard** (`storyboard.json`): per scene the stretches of the clip to use (`ranges`: from, to, speed), the on-screen caption, the camera (zoom keyframes; rectangles noted while recording are available as `mark:<name>`), and separate lengths for the short formats. Edit it and run `render`. Waits (the model thinking) are sped up on purpose; the captions never say "instantly", and the YouTube text says so.
- **Recording** (`py/record.py`, `py/scenes.py`): ffmpeg `gdigrab` at 60 fps of a 2400 x 1350 region (so zooming keeps it sharp), NVENC encoding, the pointer included. Input is `SendInput` (eased pointer paths, human-like typing, the real Ctrl+C+C, Ctrl+Shift+O and Ctrl+Shift+L). Where things are inside Owl-L's windows comes from the Chrome DevTools Protocol of WebView2 (`py/auto.py`), so the script clicks the real elements.
- **The set** (`py/stage.py`): a neutral backdrop window, bare helper windows with the made-up content (`py/article.py`, `py/viewer.py`, `ps/video-window.ps1`, and `ps/desktop-file.ps1`, which starts a genuine file drag-and-drop), and the demo build of Owl-L on a **throw-away profile** (`APPDATA` and the WebView2 folder redirected into `work/profile`, history off, no glossary; the model store is linked with a directory junction and only read).
- **Rendering** (`py/render.py`, `py/extras.py`): ffmpeg decodes, Pillow crops, zooms and overlays each frame, ffmpeg encodes. Why not Remotion: nothing to install beyond pinned ffmpeg, Pillow and numpy (no Chromium download), and the whole renderer is a few hundred readable lines. 16:9 is a plain crop; 9:16 puts the screen in a card under a large caption; 1:1 is a square crop.

## The meeting scene and the document result

- **`05b-meeting`** (`py/callwin.py`): a made-up, generic video-call window (four participants with initials, its own colours and layout, no logo of any real product). The caption area shows what meeting mode reads: an avatar with initials, the speaker name, and German text that grows word by word, then the next speaker. Owl-L is started the normal way (Ctrl+Shift+L, draw a box around the caption area); its bar shows the translation with the speaker names as labels and the turns as lines. A caption starts with three words because one word on its own is read badly by the text recognition.
- **The translated document** (`py/docpair.py`, `py/docview.py`, `ps/docx-to-pdf.ps1`): after Owl-L has translated the Word file, Word (invisible) exports the original and the result to PDF, PyMuPDF makes a picture of each page, and a helper window shows them side by side. LibreOffice is not installed here; if neither Word nor LibreOffice is available, drop the "formatting kept" caption in `storyboard.json`.

## Music, narration, beat-synced cuts

| | |
|---|---|
| Music | "A Chill Fever (Loopable)" by Tsorthan Grove, **CC0**, https://opengameart.org/content/a-chill-fever-loopable (the page states the license). Downloaded by the script into `work/music/` (not into a repository) and checked against the SHA-256 in `sources.json`. About 130 BPM. |
| Voice | Kokoro-82M v1.0 (Apache-2.0) with the voice `af_heart`, run locally with `kokoro-onnx` (MIT). Model and voice pack are downloaded into `work/tts/` and checked against `sources.json`. The wording is in `narration.json` (edit it and run `-Steps render`); other voices can be compared in `work/voice-samples/`. |
| Beats | `librosa` finds the tempo; the script fits a constant beat grid and the first downbeat (`py/audio.py`, cached in `work/music/analysis.json`). Every scene lasts a whole number of bars (at least as long as its sentence plus a pause), scene changes and camera moves start on beats, the whole video is a whole number of four-bar phrases, and the outro ends with the music. Waiting stretches are sped up or slowed down to fit; real-time stretches (the key moments) are never changed. |
| Mix | The music is faded in and out and ducked under the voice with ffmpeg `sidechaincompress` (about 17 dB under speech, 5 dB under the voice between sentences); the result is normalised to about -14 LUFS (`loudnorm`). `owll-promo-9x16-nomusic.mp4` has the voice only. Subtitles: `owll-promo-*.srt`, from the narration. |
| Credits | `E:\SecondDawn\media\out\CREDITS.txt` (written by the script from `sources.json`). |

Only the one-time downloads in `sources.json` touch the network; narration and rendering run offline.

## The caption-bar switch (demo only)

The live caption bar is hidden from screen capture on purpose (`WDA_EXCLUDEFROMCAPTURE`, so it never reads its own text). To show it in a recording, `src-tauri/Cargo.toml` has an optional cargo feature `demo-capture`: not a default feature and not enabled by any official build. Only a build made with `--features demo-capture` contains the check, and only when the environment variable `OWLL_DEMO_CAPTURE=1` is set are the caption bar and the app picker left visible. Without the feature the variable does nothing, because the code is not compiled in. `make-demo.ps1 -Steps build` makes that build into `src-tauri/target-demo` (its own folder), and `py/stage.py` sets the variable only for the app it starts.

## Privacy

All content is synthetic. Raw recordings and generated files stay outside the repositories. The original run was checked frame by frame: one frame every 1.5 seconds of every clip, and the scene boundaries of the finished videos; only the made-up windows and the backdrop are visible. Check again after changing a scene. Other programs can take the foreground (this once happened with a chat window before the staged windows were made topmost), and a notification can appear; the recorded region keeps the notification corner outside.
